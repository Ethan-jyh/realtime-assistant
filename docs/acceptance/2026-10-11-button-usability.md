# 按钮与启动流程复核

用户反馈启动入口不明显，很多按钮像没有效果。实际检查：首页模式卡片只进入准备流程；未开始的浮窗缺少开始入口；纯文字会话的暂停音频按钮仍可点击；空问题与失败操作缺少一致反馈。

修复：主页增加明确的“开始会话”；准备页在固定底部显示“开启实时辅助”，不再依赖滚动到表单末尾；空闲浮窗增加开始入口；仅有音频时允许暂停/自动，仅在生成时允许停止接收；纯文字状态与实际一致；新请求清理旧警告，失败有提示；导入使用页面内预览与确认；历史查看、打开目录、导出、移除失败显示原因；资料字段使用明确标签关联。

验证：新 e2e/buttons.spec.ts 通过本机模型验证知识问答、翻译请求内容、空输入提示、结束保存、字号改变、展开收起和启动入口。新 e2e/document-ui.spec.ts 使用合成 TXT、真实解析与上下文构造，确认导入后资料进入请求，历史详情及导出的文件包含回答。文件选择/保存对话框由测试指定临时路径；未读取私人文档。

类型检查、生产构建、62 单元测试、13 界面测试通过。当前运行的构建版两个页面已重新加载；原生界面确认主页“开始会话”与准备页固定“开启实时辅助”可见。未追加实际麦克风或外部 API 测试。此前麦克风、系统音频及 DeepSeek 链路证据另见 core-runtime.md。

## 启动与字号说明补充

后续反馈指出空白状态字号按钮看似无效果。确认 `.empty` 原先固定为 12px，虽然父容器字号变化，提示文字仍不变。修复为继承字号，同时显示字号数值，将字号与自动模式操作移至非拖拽的内容区域，收起/展开改为中文。

首页与未启动浮窗使用“设置并开始”，准备页实际启动按钮按模式显示“开始实时转写 / 开始文字会话 / 开始截图问答”，区分准备与启动。自动模式不可用的原因直接显示在操作区。

最终运行原生界面工具连续超时，未声称已在当前旧窗口做原生鼠标验证；新构建界面通过 Electron 回归测试。用户需完全退出旧实例后重新启动以加载新页面。
