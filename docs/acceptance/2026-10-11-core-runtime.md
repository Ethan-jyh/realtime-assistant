## 实际验证

- DeepSeek 官方接口：模型列表 HTTP 200，合成数组问题得到有效回答。
- 用户授权的约 10 秒内置麦克风：最终转写匹配测试短句；WAV 316844 字节，非静音；历史为 stopped、recordingSaved=true，采集窗口全部退出。
- 用户授权的 5 秒系统音频：只播放合成短句，不录麦克风；最终转写匹配；WAV 160044 字节，非静音；历史保存，采集窗口全部退出。
- 正常 npm run dev 启动：界面 DeepSeek 测试显示“连接成功”，阿里测试显示“ASR 连接成功”，后者未采集音频。
- 发现并处理测试钥匙串与正常钥匙串不一致的问题：已有两项密钥经过内存管道重新加密到正常 macOS safeStorage；原测试密文有加密备份。代码固定应用名称，测试不得再向实际用户目录写入 mock-keychain 密文。
- 回归：62 单元测试、10 Electron 界面测试；类型检查、生产构建、diff 检查通过。退出保存和启动取消测试在临时恢复缺陷的构建下明确失败，正式构建下通过。

- 固定合成网页经 Electron capturePage 生成 2400×1536 PNG，测试进程将其用作截图源。点击浮窗“截图提问”，通过正常生产 IPC、请求构造和 SSE 解析调用 DeepSeek deepseek-flash。
- 提示词不包含题目或校验码；模型从图片正确识别 7 × 8 + 9，回答 65，并输出 VISION-729。浮窗内容、completed 状态、停止后的历史记录均验证成功。
- e2e/screenshot.spec.ts 使用真实 desktopCapturer，图片只发送 127.0.0.1 本机测试服务；测试凭据是 synthetic-local-only；验证 PNG、尺寸、浮窗显示、历史保存。截图不写入验收文件，也不外发。
- 直接截取真实桌面并上传 DeepSeek 的方案被自动审批拒绝：测试页不能保证整张桌面不含私人内容。改为上述两段验证，没有进行真实桌面外发。
