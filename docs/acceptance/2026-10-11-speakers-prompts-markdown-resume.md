# 双方转写、提示词、Markdown 与暂停恢复

## 实现

- 双路标签：microphone 显示“我 · 麦克风”（蓝色），system 显示“对方 · 系统音频”（绿色）。浮窗、历史详情、文本导出及模型上下文使用相同标签。
- 系统音频中的确认发言才触发自动回答；麦克风发言仍进入上下文，但不会作为新自动问题。未手动输入问题时，优先选最后一句对方发言。
- 准备页个人信息下增加“自定义提示词”和独立保存按钮，最多 8000 字。保存为公开的本地 profile 设置，后续问答作为系统指令使用；活动会话保存后也会更新后续请求。截图请求同样保留系统提示词和资料上下文。
- 回答统一经 react-markdown + remark-gfm 渲染：浮窗、配置页预览和历史详情支持标题、粗体、列表、代码块、表格。禁用原始 HTML 执行及远程图片自动加载，链接保留安全 URL 转换。
- 暂停时结束当前 ASR 任务，停止发送/保存 PCM；继续时为每路重新建立任务，等待采集页确认 AudioContext 恢复。保持同一会话 ID、录音写入器和已有转写；新 streamEpoch 防止重复句子 ID 覆盖旧记录。
- 恢复失败维持暂停状态并显示原因，可重试；切换期间按钮禁用。停止识别任务共享 Promise，避免暂停与结束并发覆盖收尾回调。

## 验证

- 65 单元测试、16 Electron 界面测试；类型检查、生产构建和 diff 检查通过。
- 本机 ASR/模型与无硬件采集测试桩验证：自己的发言不自动调用模型，对方会触发；暂停后建立新任务、继续转写，失败后仍暂停且可成功重试。
- 提示词确实写入 assistant-settings.json，文字与合成截图请求携带自定义系统指令；双方相同句子 ID 不合并，手动问答选择对方问题。
- Markdown 流式片段渲染为真实标题、strong、列表、pre/code 与 table；模型提供的 script 不执行、javascript 链接无可执行 href。历史里的粗体也渲染。
- 真实阿里 qwen-audio-3.1-asr-flash-streaming：使用已有合成 WAV，第一轮识别后暂停，再建立任务并识别同一合成语音。结果 sameSession=true，state=stopped，finalCount=2，epochs=[1,2]，secondRecognized=true。没有采集麦克风或系统实际声音。

## 使用与边界

新版本涉及主进程更新，必须从菜单完全退出旧实例再双击启动入口。双方区分选择“我（麦克风）+ 对方（系统音频）”；麦克风串音、应用播放的其他音频可能影响来源判断。它不是声纹或多人说话人分离，同一路多个人仍显示“对方”。

自定义提示词在“设置并开始 → 个人信息”编辑，点击“保存提示词”。例如：请用中文自然口语回答，先给结论，再给两点依据和一个短例子；不编造经历；信息不够时说明缺少什么。提示词影响后续请求，不会改写已经生成的旧回答。

## 完整对话上下文补充

用户要求自己的话不触发自动回答，但模型必须收到本次会话双方的完整发言记录。已移除确认转写的 16000 字符尾部截断，按保存顺序编号并标注“我 · 麦克风 / 对方 · 系统音频”。回答、资料问答、截图及翻译请求均携带完整已确认转写；临时、可能更正的非 final 转写不作为确认记录重复发送。

结束当前会话后、未开启下一会话前，继续追问仍携带本会话转写。回归测试覆盖超过旧窗口长度的 30 条双方发言，验证从第一条到最后一条均存在，并验证结束后追问仍包含暂停前后和自己的发言。

不会为适配模型而静默删掉会话记录；若所配置接口拒绝过长上下文，则保留记录并显示接口错误。此处完整指应用已经识别并确认的本次会话记录，不能补回识别失败或没有采集到的音频。
