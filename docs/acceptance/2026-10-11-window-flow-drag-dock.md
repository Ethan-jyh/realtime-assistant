# 窗口顺序、拖动和 Dock

启动仅创建并显示准备页。会话采集初始化成功后才创建/显示浮窗，准备页同时隐藏。设置与返回会话由 WindowManager 的 activeView 统一控制，迟到的 ready-to-show 不会重新显示非当前窗口。新会话展开浮窗并清理上次界面输出；编辑设置时显示“返回当前会话”，不会重复开始。

窗口四周、外边距和空白区域使用 app-region:drag；按钮、输入、下拉框、回答正文和滚动区域使用 no-drag。macOS 首次点击可直接操作，显式切换时窗口获得焦点。取消窗口加载的预期异常被处理，实际加载失败仍记录错误。

按用户选择采用隐藏底部 Dock 图标方案，没有新建图标素材。macOS app.dock.hide 在启动时调用；跨工作区窗口设置使用 skipTransformProcessType，避免窗口切换重新改变应用类型。

验证：类型检查、生产构建、65 单元测试、18 Electron 界面测试通过。新 window-flow 测试验证初始只有一个准备窗口、启动后仅浮窗可见、设置/返回后仍只有当前窗口可见、Dock API 状态保持隐藏，以及拖动与交互区域的实际计算样式。既有测试按显式预览操作创建浮窗，不再把自动弹出浮窗作为正常启动行为。

拖动区域已由计算样式验证，本轮未通过原生 UI 工具实测鼠标移动距离；不声称完成该项硬件操作验收。新版本涉及主进程，用户必须完全退出旧应用再重新启动。
