# 稳定性改进候选版 0.2.23 验证

## 代码改动

1. 主入口与 React 页面纯格式化单独提交。
2. Runtime 使用 Electron 44.7 的官方异步 safeStorage；不回退同步调用。配置查询仅读密钥存在索引，旧格式无索引时为 unknown。启动不解密迁移旧密钥，真正读取时用别名兼容旧 keyId。
3. Vault 等待限制 8 秒、共享读取与初始化、串行保存；超时和解密失败不覆盖密文，迟到结果不允许写盘。首次主动成功保存保留原密文 before-async 备份，备份不随随后保存覆盖。系统操作没有被取消。
4. 快/深回答增加 sessionKey / turnKey / requestKey / lane、排队等待、实际发送、首个非空输出与终止汇总。关联 ID 为 SHA-256 摘要前 16 位；日志不包含问题、回答或密钥。TTFT 从最后一次请求实际发送到首个正文 token，不把策略/密钥等待混成上游 TTFT。
5. 模型路由和公开配置初始化抽离。没有合并音频/修饰键原生进程，没有重写拖拽或强制缩减入口行数。
6. 固定签名后自动运行通过 LaunchServices 启动的安装包探针，验证桥接、资源与可执行文件；基本探针不使用真实密钥。独立监督程序超时收集 sample，结束测试实例。

## 通过的验证

- TypeScript 类型检查、构建通过。
- Vitest 44 个文件、217 项测试通过。
- 分批关键 Electron 回归通过：窗口销毁/重开、托盘和 Dock、模型连续问答、Codex 模拟后端、快深并排与关联日志、密钥异步永不返回情况下的首页/设置响应。最后针对最终构建重跑并排回答和密钥阻塞两项，均通过。
- 完整实体依赖目录打包，固定证书 strict/deep 签名检查及隔离配置产物启动探针通过。开发时用依赖软链接导致构建器漏收集间接依赖，已改为实体目录并核对 jszip/mammoth 等位于 ASAR。

## 未通过的发布门槛

当前机器的既有 secrets.vault 临时副本只读检查，以及暂时放在原安装路径的同签名检查，均在异步初始化阶段 8 秒超时。原配置所有受检文件哈希保持不变。

线程采样显示 ThreadPoolForegroundWorker 等待 SecItemCopyMatching / SecurityServer decrypt，主线程处于正常 AppKit 事件循环；不再出现同步钥匙串阻塞主线程。该证据没有证明密文格式不兼容，也没有证明一定是 ACL 弹窗。

原路径验证后恢复已安装 0.2.21，0.2.23 尚未部署。需要继续确认系统钥匙串等待的原因；没有重置 TCC、扩大权限或修改钥匙串访问控制。辅助进程图标改动的语音面板效果仍未验证，不能宣称图标已修复。
